# Contributing

Thanks for taking the time to help. Small, focused contributions are the easiest to review and merge.

1. **Search first** — check open issues and discussions to avoid duplicates.
2. **Open an issue** for anything bigger than a typo, so we can agree on the approach before you write code.
3. **Fork → branch → PR.** One logical change per pull request, with a clear description of *what* and *why*.
4. **Use [Conventional Commits](https://www.conventionalcommits.org/)** (`feat:`, `fix:`, `docs:` ...). Releases are generated from them.
5. **Test your change** and make sure CI is green before requesting review.

Questions or ideas that are not bugs belong in **Discussions**. Be kind — see the [Code of Conduct](CODE_OF_CONDUCT.md).
